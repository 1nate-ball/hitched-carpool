## Field contract

| Form field / source | Existing JS property | SQL column | Type | Rule |
|---|---|---|---|---|
| Generated by database | `id` | `id` | UUID | Primary key; returned after insert |
| Signed-in session | `driver` | `driver_id` | UUID | Required; references `auth.users.id`; defaults to caller; RLS rejects another user's ID |
| Destination (`pt-dest`) | `dest` | `destination_id` | text | Required; one of the existing 8 destination IDs |
| Departure date + time (`pt-date`, `pt-time`) | `depart` | `departure_at` | timestamptz | Required; after the real current time at insert |
| Pickup (`pt-pickup`) | `pickup` | `pickup_location` | text | Required; whitespace-only rejected |
| Drop-off (`pt-dropoff`) | `dropoff` | `dropoff_location` | text | Required; whitespace-only rejected |
| Available seats (`pt-seats`) | `seats` | `total_seats` | integer | 1–7 passenger seats, excluding driver |
| Price per seat (`pt-price`) | `price` | `price_per_seat` | integer | Whole US dollars, 1–150; matches current form |
| Return date + time (`pt-rdate`, `pt-rtime`) | `ret` | `return_at` | nullable timestamptz | NULL for one-way; otherwise strictly after departure |
| Generated by database | none | `created_at` | timestamptz | Automatic creation timestamp |

The return checkbox is UI state: unchecked sends `return_at: null`; checked requires both return inputs. No separate `has_return_trip` column is needed. A non-null return means the price covers both directions, matching the current copy. `total_seats` stores offered capacity, not remaining availability; accepted requests can determine remaining seats later.

The existing form does **not** collect vehicle information: it assigns `vehicle: 'Your vehicle'`. Do not store that placeholder as real information. Proposed scope is to omit a vehicle column for now; when displaying a database trip, hide the vehicle line until a real field is added. There is also no separate origin-city field today; pickup is free text. Origin search needs its own later agreement.

## Time handling

Keep a single database timestamp even if the UI combines date and time into `datetime-local`. `datetime-local` itself carries no timezone. Proposed rule for this BYU prototype: entered trip times mean **America/Denver**, including daylight saving time. Robbie must convert the selected wall time using that zone and send an ISO timestamp with an offset (or UTC). Do not append `Z` to the raw input, and do not rely on the browser's timezone when a user is outside Utah. Display stored times in America/Denver too. Reject or resolve ambiguous/nonexistent daylight-saving transition times before sending.

The prototype's `NOW` is fixed to October 3, 2026. Replace that comparison with the actual current time when connecting the form. The database trigger independently rejects past departures at creation. The setup offers no client update/delete permissions yet.

## Identity and permissions: decision needed before integration

The database uses Supabase Auth UUIDs, not the prototype string `'me'`. The policies permit signed-in users to read trips/destinations and create trips as themselves; signed-out visitors cannot read or write these tables. There are no client update/delete permissions. Grants and RLS are both explicit, following [Supabase's RLS guidance](https://supabase.com/docs/guides/database/postgres/row-level-security).

This creates an integration dependency because sign-in is currently future backlog work. For development, the team can use two test accounts signed in through Supabase Auth; a complete signup UI is not required to test the schema. If the team instead chooses a server-managed demo identity, revise this contract and the backend together before changing the existing setup. Do not enable unrestricted anonymous inserts or put a secret/service-role key in browser code.

The visual “ID verified” badge and frontend check are prototype data. This schema does not verify BYU membership or student identity. Production verification permissions are a separate backlog item.

## Acceptance checks for Nate's test card

- A signed-in driver creates a valid one-way trip; saved row has their UUID and NULL return.
- A valid round trip saves both timestamps; return equal to/before departure fails.
- Seats 1 and 7 and prices 1 and 150 succeed. Seats 0, 8, fractional seats; prices 0, 151, fractional prices; missing/blank fields; unknown destinations; and past departures fail.
- Missing timestamps and return-checkbox inputs are caught beside the form. Database errors keep form values and show a visible retryable error; a failed save never displays success.
- Driver A cannot insert a trip attributed to driver B. Signed-out reads/inserts and client updates/deletes fail. Test using user sessions/publishable key; SQL Editor/admin credentials bypass RLS and do not prove client permissions.
- Driver B can read A's saved trip after refreshing in a second signed-in browser; test returned field values, not just row count.
- UTC conversion/display round-trips correctly; check an out-of-Utah browser and dates around daylight-saving transitions.
- The running form uses real current time, not the prototype clock. Check double-click/retry behavior; the current schema has no idempotency key, so Robbie must prevent concurrent duplicate submissions and reconcile uncertain results before retrying.

## Wiring example

Use the saved Auth session, map the form values to the field contract, and only show success after `publishTrip` resolves:

```js
import { publishTrip, loadTrips } from '/hitch-supabase.js';

// session comes from Supabase Auth. departureISO/returnISO include timezone.
const savedTrip = await publishTrip(session.access_token, {
  destination_id: destinationId,
  departure_at: departureISO,
  pickup_location: pickup.trim(),
  dropoff_location: dropoff.trim(),
  total_seats: Number(seats),
  price_per_seat: Number(price),
  return_at: includeReturn ? returnISO : null,
});
// Use savedTrip.id for navigation. Reload saved rows instead of resetting to sample trips.
const trips = await loadTrips(session.access_token);
```

Run the app through `python3 server.py`, not by opening the HTML file directly. If using the current inline non-module script, dynamically import the helper inside an async submit handler. Keep the token out of source code.
